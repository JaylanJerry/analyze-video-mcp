# 主审核关卡

适用于当前 1.0 媒体网关的维护。普通修改按仓库门禁完成；方向变更和外部操作遵守用户授权。证据必须脱敏。

## 1. 规格与公开契约

- 对照 [当前规格](SPEC_MEDIA_GATEWAY.md)、[API 契约](API_CONTRACT.md) 与 ADR 0024/0025。
- 唯一入口 `analyze_media(media, prompt)`，Agent 决定问题；不恢复旧 Tool 或强制报告层。
- 变更默认值、上限、生产依赖、运行时或公开字段时，先提交具体方案并取得所需授权。

## 2. 安全与资源

- 本地允许根、内容检查、同句柄授权与上传、取消及超时分类正确。
- 大文件流式处理，保持有界探测；不整文件 Base64，不隐式转码。
- 不泄漏密钥、policy、OSS URL、本地路径；公开 HTTPS 链接保留。
- 缓存隔离与指纹按实际保证描述，不把中段改写残余或 TOCTOU 写成已消除。
- 用免费回归测试与完整质量门验证，必要时检查内存与句柄证据。

## 3. 协议、安装与宿主

- SSE、usage、推理文本过滤与 Provider 错误映射符合契约。
- 打包安装、stdio 初始化、版本与 `listTools()` 一致。
- GUI 拖入、结果展示与长答案交付分别记录；不得用脚本调用替代宿主证据。
- 真实付费调用必须明确授权，结果只证明当次请求，不外推模型能力。

## 4. 发布

- 当前支持 Node 24.x；本地质量门、覆盖率、安装专项与远程阻塞 CI/Secret Scan 均通过。
- 文档区分实现、mock、live、宿主与正式发布；已知限制如实保留。
- 提交、推送、PR、合并、tag 与 npm 发布遵守用户授权；按 ADR 0014 使用 Trusted Publishing，不添加 NPM_TOKEN 或绕过钩子。
- 官方 registry 重新安装并核对版本、握手和包内容后，才能记录发布完成。
