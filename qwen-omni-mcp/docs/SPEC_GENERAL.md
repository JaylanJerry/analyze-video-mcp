# Video MCP 通用方向规格

状态：已批准。G01–G06 已实施。完整情况见 [`SPEC_V2.md`](SPEC_V2.md)。

范围批准依据：用户确认 v1 本机已够用，要转向“对人一次配置、对 Agent 一项原生能力”。

实现状态：G01–G06 已完成，未发布。任务在 [`../tasks/todo-general.md`](../tasks/todo-general.md)。

## 1. 目标

把现有专项做成可换机器安装的视频理解 MCP。Agent 体验不变：传入视频和问题，拿回文本。人的体验改成标准 MCP 安装：自己填写密钥、允许目录和可选地址。

本地文件上限对齐百炼临时上传政策（1024 MiB），而不是 v1 的 500 MiB 验收保守值。

## 2. 保持不变

- 唯一 Tool：`analyze_video(video, question?)`。
- 成功只返回文本；错误脱敏。
- 本地路径默认拒绝，必须在 `QWEN_ALLOWED_ROOTS` 内。
- 本地主路径：授权 FileHandle → 流式 multipart → `oss://` → SSE 聚合。
- 禁止 Base64、整文件 `readFile()`、新增生产依赖、自动重传整个大文件。
- 不发布、不推送，除非用户另说。

## 3. 要改的

| 项           | v1                                 | 通用方向                               |
| ------------ | ---------------------------------- | -------------------------------------- |
| 本地默认上限 | 500 MiB                            | 1024 MiB                               |
| 本地硬顶     | 500 MiB                            | 1024 MiB，且不超过当场 policy          |
| Host 安装    | 本机脚本读 `text/*.key`            | 用户在 Host `env` 自己填               |
| 端点         | 代码默认北京区                     | 仍默认北京区；用户可填 URL             |
| 长视频回答   | Agent 可传 `max_tokens`，默认 1024 | 从 Tool 去掉该字段；内部按模型最大输出 |

## 4. 给 Agent 的契约

V2 批准后的契约：Tool 只保留 `video` 和 `question`。去掉 `max_tokens`。实施时改 [`API_CONTRACT.md`](API_CONTRACT.md)。

不把 key、模型、上传方式、OSS、回答长度旋钮放进 Tool。内部按模型最大输出生成回答。

`video` 继续接受：

- 允许根内的本地绝对 MP4；
- 公开 `https://` URL（本机不下载）。

## 5. 给用户的配置

安装时只通过进程环境变量，不提供 GUI。

| 环境变量                  | 必需         | 默认                   | 说明                                                   |
| ------------------------- | ------------ | ---------------------- | ------------------------------------------------------ |
| `DASHSCOPE_API_KEY`       | 是           | 无                     | 用户自己填写。只存在本机 Host 配置或本机环境，不得提交 |
| `QWEN_ALLOWED_ROOTS`      | 本地路径时是 | 空                     | 用户自己填写绝对目录                                   |
| `DASHSCOPE_BASE_URL`      | 否           | 北京区兼容模式推理地址 | 用户可改                                               |
| `DASHSCOPE_UPLOAD_URL`    | 否           | 北京区临时上传地址     | 用户可改                                               |
| `QWEN_MAX_LOCAL_VIDEO_MB` | 否           | `1024`                 | 1–1024。实际上传前再与当场 policy 取较小值             |
| `QWEN_MODEL`              | 否           | `qwen3.5-omni-flash`   | 内部配置                                               |
| `QWEN_UPLOAD_TIMEOUT`     | 否           | `900`                  | 秒                                                     |
| `QWEN_ANALYSIS_TIMEOUT`   | 否           | `900`                  | 秒                                                     |

产品安装文档提供 Cursor、Claude Code、Codex 三份无密钥模板。本机 `text/*.key` 启动脚本可以留着给这个仓库开发用，README 主路径不再依赖它。

## 6. 本地上传与网速

本地文件 ≤ 1024 MiB 且不超过当场 policy 时，**直接流式上传并分析**。不先测速，不先劝用户改用链接。

网速不够的判定只看上传是否在凭证/超时内完成，不另做带宽探测：

- 上传超时；
- 临时上传凭证过期（实测约 300 秒）；
- 上传中连接中断。

此时返回 `VIDEO_UPLOAD_FAILED`，Agent 可见文本必须明确建议：把视频放到公开 HTTPS 地址，再把该链接传给 `analyze_video`。不自动重传整个文件，不自动改走 URL，不弹 GUI。

1 GiB 要在约 300 秒内传完，持续上行大约需要 28 Mbit/s。工具描述里用一句话提醒慢网可改用 HTTPS；真正失败时再给出上述错误文本。

## 7. 边界条件

必须全部写进实现和测试，缺一条不算通用方向完成。

### 7.1 本地文件

| 条件                                                         | 行为                                                      |
| ------------------------------------------------------------ | --------------------------------------------------------- |
| 0 < 大小 ≤ `min(用户上限, 当场 policy)`，且 ≤ 1024 MiB       | 直接上传分析                                              |
| 空文件                                                       | `UNSUPPORTED_VIDEO` 或 `INVALID_VIDEO_INPUT`，上传 0 字节 |
| 大于用户上限或大于当场 policy 或大于 1024 MiB                | `VIDEO_FILE_TOO_LARGE`，上传前失败；可提示压缩/切段/HTTPS |
| 非绝对路径、不在 `QWEN_ALLOWED_ROOTS`、越界 symlink/junction | `VIDEO_PATH_NOT_ALLOWED`                                  |
| 不存在、不可读                                               | `VIDEO_NOT_FOUND`                                         |
| 非普通文件、非 MP4 扩展名、magic 不符                        | `UNSUPPORTED_VIDEO`                                       |
| 未配置允许根                                                 | 拒绝全部本地路径；HTTPS 不受影响                          |

不探测时长。模型侧 URL 视频文档上限约 1 小时；本地不引入 ffprobe，也不因时长拒绝。

### 7.2 远程 URL

| 条件                                        | 行为                                                        |
| ------------------------------------------- | ----------------------------------------------------------- |
| 公开 `https://`                             | 本机不下载，直接交给百炼                                    |
| `http://`、`file://`、`data:`、带用户名密码 | `INVALID_VIDEO_INPUT`                                       |
| localhost / 明显回环或私网字面量            | `INVALID_VIDEO_INPUT`                                       |
| 链接失效、需登录、百炼拉不到                | `VIDEO_ANALYSIS_FAILED` 或 provider 类错误，不泄露 URL 细节 |

### 7.3 运行与并发

| 条件                   | 行为                                          |
| ---------------------- | --------------------------------------------- |
| 已有一个上传或分析     | `VIDEO_ANALYSIS_BUSY`，不排队、不读第二个文件 |
| Host 取消 / 进程退出   | 中止上传和推理，释放句柄与锁                  |
| 缺 `DASHSCOPE_API_KEY` | 启动失败，错误不含密钥值                      |
| 问句超过 8000 字符     | `INVALID_VIDEO_INPUT`                         |
| 429 / 502 / 503        | 现有有限重试；上传失败整文件不重传            |
| 推理已出首字节后失败   | 不重试                                        |

### 7.4 安全与输出

| 条件     | 行为                                |
| -------- | ----------------------------------- |
| 任何错误 | 不含 key、policy、OSS、本地绝对路径 |
| 成功     | 只回模型文本                        |
| 回答长度 | Agent 不可调；内部用模型最大输出    |

### 7.5 明确不做的边界处理

- 不测速、不弹系统窗口、不自动转码、不代下 URL 再上传。
- 不因「可能慢」而预先拒绝 ≤1024 MiB 的本地文件。
- 不上正式 OSS 来绕过 300 秒凭证。

## 8. 非目标

- GUI、Web 控制台、进度面板。
- 图片 / 独立音频等额外 Agent Tool。
- 把 key 或模型放进 Tool 参数。
- 正式 OSS、npm 发布、Windows exe。
- 服务端代下任意 URL 再上传。
- 新增生产依赖。
- 为迁就 Host 超时而改成异步 job 轮询（先用现有长超时；进度通知单独成阶段，失败也不回退 Phase 1）。

## 9. 完成标准

- 用户只靠 README 模板和自己的 key，能在新机器上配置 Cursor 并分析本地 MP4。
- `QWEN_MAX_LOCAL_VIDEO_MB=1024` 为默认；设 500 仍可收紧。
- 大于 500、小于等于 1024 且不超过当场 policy 的本地 MP4 不再被产品硬顶拒绝。
- 当场 policy 若低于用户配置，仍在上传前拒绝。
- 上传超时或凭证过期时，错误文本建议改用公开 HTTPS，且不自动重传。
- `analyze_video` 名称不变；公开字段为 `video`、`question`。
- 仓库模板和文档不含密钥。
- 质量门与现有门槛相同。

## 10. 与硬规则的关系

| 现行规则                                   | 冲突                                 | 处理                                              |
| ------------------------------------------ | ------------------------------------ | ------------------------------------------------- |
| 不改变 `analyze_video` 公开契约            | V2 去掉 `max_tokens`，本地上限也会变 | 用户已批准该契约变更；名称仍是 `analyze_video`    |
| 本地最大 500 MiB（SPEC / ADR 0002 / 0004） | 要升到 1024                          | 本规格与 ADR 0009 批准后取代该上限                |
| 不建议把 key 写入 Host 配置                | 通用安装需要用户自填 `env`           | 允许写入本机、已 gitignore 的 Host 配置；禁止提交 |
| 一次只做 `todo.md` 一项                    | v1 todo 已收尾                       | 改做 `todo-general.md`，一次一项                  |
| 不增加生产依赖、不推送、不发布             | 无冲突                               | 继续遵守                                          |

## 11. 假设

本规格假设百炼临时上传政策仍约为 1024 MB、凭证约 300 秒。若政策下降，动态检查继续有效，只是默认 1024 会在上传前失败。若用户上行传不完 1 GiB，产品报错并建议 URL，不在本阶段上正式 OSS。
