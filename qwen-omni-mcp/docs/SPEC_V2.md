# Video MCP V2 规格

状态：已批准并实施 G01–G06。未发布。

V2 是 v1 的通用化，不是另一个产品。Agent 仍然只看到一个 `analyze_video`。变的是：本地最高 1 GiB、用户自己填 MCP 配置、网速不够时用文字提示改走公开 HTTPS、回答长度交给模型自身上限。

v1 记录见 [`SPEC.md`](SPEC.md)。实施任务见 [`../tasks/todo-general.md`](../tasks/todo-general.md)。本文件是给人口读的完整情况表；和本文件冲突时，以本文件为准，再回写 ADR。

---

## 1. 一句话

人装一次 MCP，填密钥和允许目录。之后对 Agent 说「看这个视频」，它传入本地 MP4 或公开 HTTPS，工具同时看画面、听音轨，只回一段文本。

本地文件不超过 1 GiB 就直接上传分析。上传因网速或凭证失败，不重传整文件，只告诉用户：改成公开 HTTPS 链接再分析。

---

## 2. 和 v1 的差别

|                 | v1                                             | V2                                                                    |
| --------------- | ---------------------------------------------- | --------------------------------------------------------------------- |
| 给 Agent 的工具 | `analyze_video(video, question?, max_tokens?)` | `analyze_video(video, question?)`，去掉 `max_tokens`                  |
| 本地默认上限    | 500 MiB                                        | 1024 MiB                                                              |
| 本地硬顶        | 500 MiB                                        | 1024 MiB，且不超过当场百炼政策                                        |
| 安装            | 本仓库脚本读 `text/*.key`                      | 用户在 Host `env` 自己填                                              |
| 端点            | 写死北京区默认                                 | 仍默认北京区，用户可改 URL                                            |
| 网速不够        | 只报上传失败                                   | 失败文本明确建议改用公开 HTTPS                                        |
| 回答长度        | Agent 可传 `max_tokens`，默认 1024、上限 8192  | Agent 不传。内部不卡 8192，按模型最大输出（当前 65536）或省略该字段   |
| 连通测试        | 无独立 Tool                                    | 仍无。启动只检查配置是否缺项；第一次分析失败时用错误文本说明 Key/地址 |
| 发布            | 不发布                                         | 仍不发布，除非另批                                                    |

## 3. 谁用、在哪用

- 单人、本机 Agent。不是多租户服务。
- 主环境：Windows。Cursor、Claude Code、Codex 共用同一 `dist/index.js`。
- 人负责：填密钥、填允许读哪些文件夹、可选改接口地址。
- Agent 负责：传入视频和问题，阅读返回文本或错误码。
- Agent 不需要知道模型名、OSS、上传、抽帧。

## 4. 公开工具

```text
analyze_video(video, question?) -> 文本
```

| 字段       | 必需 | 默认                               | 含义                                      |
| ---------- | ---- | ---------------------------------- | ----------------------------------------- |
| `video`    | 是   | 无                                 | 本地绝对 MP4 路径，或公开 `https://` 链接 |
| `question` | 否   | `画面里发生了什么？音频说了什么？` | 1–8000 字符                               |

禁止出现在 Tool 里：`max_tokens`、`model`、`api_key`、`provider`、`upload`、`oss_url`、`thinking`、`audio`、`frames`。

回答长度不给 Agent 旋钮。请求里不传 `max_tokens`，或传到当前模型文档的最大输出（`qwen3.5-omni-flash` 现为 65536）。模型写完就停，按实际输出计费。这是批准过的契约变更，实施时改 [`API_CONTRACT.md`](API_CONTRACT.md)。

成功：一段模型文本，不加标题、request id、路径、用量。

失败：`错误码: 说明。` 说明里可以建议下一步，但不能含密钥、policy、OSS、本地绝对路径。

内部固定包一层：必须同时依据画面和内嵌音轨作答；没有可用声音要明说。

## 5. 两条主路径

```text
本地 MP4
  校验路径 / 类型 / 大小
    -> 取临时上传凭证
    -> 流式上传（不整文件进内存、不 Base64）
    -> 用 oss:// 做 SSE 推理
    -> 只回文本

公开 HTTPS
  校验 scheme / 不带账号 / 不是本机或私网字面量
    -> 本机不下载
    -> 把链接交给百炼做 SSE 推理
    -> 只回文本
```

网速只影响本地路径。HTTPS 路径不经过本机上传。

## 6. 人怎么配置

没有图形界面。在 Cursor / Claude Code / Codex 的 MCP `env` 里填写。

| 变量                      | 谁填               | 默认                   | 说明                                                 |
| ------------------------- | ------------------ | ---------------------- | ---------------------------------------------------- |
| `DASHSCOPE_API_KEY`       | 用户必填           | 无                     | 只放本机，不要提交                                   |
| `QWEN_ALLOWED_ROOTS`      | 否                 | 空                     | 可选。空 = 分析这次传入的本地绝对 MP4；填写后只允许这些目录 |
| `DASHSCOPE_BASE_URL`      | 可选               | 北京区兼容模式推理地址 | 换区或专属网关时改                                   |
| `DASHSCOPE_UPLOAD_URL`    | 可选               | 北京区临时上传地址     | 同上                                                 |
| `QWEN_MAX_LOCAL_VIDEO_MB` | 可选               | `1024`                 | 只能 1–1024，可主动收紧                              |
| `QWEN_MODEL`              | 一般不填           | `qwen3.5-omni-flash`   | 不进 Tool                                            |
| `QWEN_UPLOAD_TIMEOUT`     | 可选               | `900` 秒               | 本机上传超时                                         |
| `QWEN_ANALYSIS_TIMEOUT`   | 可选               | `900` 秒               | 推理超时                                             |

缺密钥：进程启动失败，错误里不能出现密钥内容。

本仓库读 `text/*.key` 的脚本只给开发用，不算 V2 安装方式。

### 配置能不能连上

不要做独立的「测试连接」Tool，也不要在每次启动时打一次付费或政策接口。

| 情况                                               | 结果                                                                                                  |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Host 能拉起进程并完成 MCP `initialize`             | 配置文件和命令是通的。只说明进程活着，不证明 Key 能调百炼                                             |
| 缺 `DASHSCOPE_API_KEY`、允许根非法、URL 不是 HTTPS | 启动失败。Host 会显示 MCP 挂了。错误不含密钥                                                          |
| Key 填了但无效、地址填错、账号没开模型             | 进程能起来。第一次 `analyze_video` 返回鉴权/不可用类错误，文本写：检查 API Key 和接口地址。不泄露 Key |
| 网络当时不通                                       | `PROVIDER_UNAVAILABLE` 或上传/政策失败，可稍后重试                                                    |
| 用户想确认配好了                                   | 用很小的本地 MP4 或公开 HTTPS 调一次 `analyze_video`。这就是连通测试                                  |

启动时做真实探测会让每次打开 Cursor 都打外部 API，失败原因和「MCP 红点」搅在一起，也不省事。v1 已删掉 `check_endpoint_status`，V2 不恢复。

## 7. 大小、政策和网速

实际上传上限：

```text
上限 = min(用户 QWEN_MAX_LOCAL_VIDEO_MB, 当场 policy.max_file_size_mb, 1024 MiB)
```

允许上传：`0 < 文件字节 ≤ 上限`。

政策当场是 1024 MB 时，默认配置下本地最高就是 1 GiB。政策若降到 800，即使用户写了 1024，800 MiB 以上也在上传前拒绝。

不先测网速。只要文件没超上限，就直接传。

「网速不够」只在上传已经失败后认定：

1. 本机上传超时；
2. 临时凭证过期（实测约 300 秒）；
3. 上传中连接中断。

1 GiB 要在约 300 秒内传完，持续上行大约需要 28 Mbit/s。这是说明，不是启动前检查。

失败后：

- 错误码：`VIDEO_UPLOAD_FAILED`
- 给 Agent 的说明必须包含：请将视频放到可公网访问的 HTTPS 地址，再把该链接传给本工具。
- 不自动重传整文件。
- 不自动改成本地下载或改走别的存储。
- 不弹系统窗口。MCP 没有统一弹窗，「提示」就是这段错误文本，由 Host/Agent 显示给用户。

工具描述里用一句话提醒：大文件若上行很慢，可改用公开 HTTPS。这不是预拒绝。

临时对象在北京区，大约 48 小时后自动删除。V2 不提供手动删除。

## 8. 情况总表

下面每一种都要有确定行为。没有「看情况再定」。

### 8.1 安装与配置

| 情况                                               | 结果                                   |
| -------------------------------------------------- | -------------------------------------- |
| 用户填了密钥和允许目录，分析该目录下 MP4           | 走本地上传                             |
| 只填了密钥，没填允许目录，传入本地路径             | 分析这次传入的绝对 MP4。HTTPS 仍可用 |
| 没填密钥                                           | 服务起不来                             |
| 允许目录不是绝对路径、不是已存在的目录             | 启动失败                               |
| 用户把上限设成 500                                 | 501 MiB 本地文件被拒，500 MiB 可以     |
| 用户把上限设成 1025                                | 启动失败                               |
| 用户把密钥写进本机 `mcp.json` 且该文件被 gitignore | 允许                                   |
| 有人把真实密钥提交进仓库                           | 禁止。钩子和文档必须挡住               |
| 用户改了 Base/Upload URL，但不是 HTTPS             | 启动失败                               |
| 换一台新电脑，按 README 模板自己填 key             | 应能用，不依赖本仓库的 `text/*.key`    |

### 8.2 本地文件

| 情况                                          | 结果                                                           |
| --------------------------------------------- | -------------------------------------------------------------- |
| 允许根内、普通 MP4、1 字节到上限              | 直接上传分析                                                   |
| 中文文件名、中文目录、空格、Windows 反斜杠    | 允许                                                           |
| 空文件                                        | 上传前拒绝，`UNSUPPORTED_VIDEO` 或 `INVALID_VIDEO_INPUT`       |
| 大于用户上限、大于当场政策、或大于 1024 MiB   | `VIDEO_FILE_TOO_LARGE`，0 字节上传。可提示压缩、切段或改 HTTPS |
| 相对路径、`~/video.mp4`、只有文件名           | `INVALID_VIDEO_INPUT` 或 `VIDEO_PATH_NOT_ALLOWED`              |
| 路径在允许根外                                | `VIDEO_PATH_NOT_ALLOWED`                                       |
| 允许根内的 junction/symlink，最终目标仍在根内 | 允许                                                           |
| junction/symlink 跳到根外                     | `VIDEO_PATH_NOT_ALLOWED`                                       |
| 文件不存在、无读权限                          | `VIDEO_NOT_FOUND`                                              |
| 目录、盘符、管道、设备                        | `UNSUPPORTED_VIDEO`                                            |
| 扩展名不是 `.mp4`（大小写不敏感除外）         | `UNSUPPORTED_VIDEO`                                            |
| 扩展名是 mp4 但文件头不是 MP4                 | `UNSUPPORTED_VIDEO`                                            |
| `.mp4.key` 或文本伪装                         | `UNSUPPORTED_VIDEO`，且不得把内容读进错误                      |
| 检查后、上传前文件被换成别的                  | 身份复检失败，拒绝上传                                         |
| 时长 7 分钟但体积 564 MiB（小于 1 GiB）       | 直接上传，不因时长拦截                                         |
| 时长 2 小时但体积 200 MiB                     | 本机不按时长拒绝；模型能否看完由百炼决定                       |
| 不探测、不转码、不抽帧、不抽音轨              | 固定如此                                                       |

### 8.3 公开 HTTPS

| 情况                                                 | 结果                                                                                                 |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 可公网访问的 `https://...mp4`                        | 本机不下载，直接给百炼                                                                               |
| `http://`                                            | `INVALID_VIDEO_INPUT`                                                                                |
| `file://`、`data:`、`ftp://`、无协议                 | `INVALID_VIDEO_INPUT`                                                                                |
| URL 里带用户名密码                                   | `INVALID_VIDEO_INPUT`                                                                                |
| `https://127.0.0.1/...`、`localhost`、明显私网字面量 | `INVALID_VIDEO_INPUT`                                                                                |
| 内网域名但字面量不是私网 IP                          | V2 不做 DNS 判断，交给百炼；拉不到再报分析失败                                                       |
| 链接 404、要登录、防盗链                             | provider 类错误或 `VIDEO_ANALYSIS_FAILED`，不回完整 URL                                              |
| 链接指向大于 1 GiB 的对象                            | 本机不下载，因此不受 1 GiB 本地上限约束；能否分析由百炼文档/政策决定（URL 视频文档约 2 GB / 1 小时） |
| 用户先把本地大文件放到对象存储，再把 HTTPS 传来      | 这是网速不够时的正路                                                                                 |

### 8.4 上传与网速

| 情况                                         | 结果                                                     |
| -------------------------------------------- | -------------------------------------------------------- |
| 文件未超上限，上行足够，300 秒内传完         | 继续推理                                                 |
| 文件未超上限，上行不够，超时或凭证过期或断线 | `VIDEO_UPLOAD_FAILED`，提示改用公开 HTTPS。不自动重传    |
| 还没开始传就超上限                           | `VIDEO_FILE_TOO_LARGE`，不是上传失败                     |
| 取凭证失败                                   | `UPLOAD_POLICY_FAILED`，可稍后重试，不提示「你网速不行」 |
| 取到凭证后政策上限小于文件                   | 任何字节都不传，`VIDEO_FILE_TOO_LARGE`                   |
| 上传成功、推理失败                           | 允许用已有 `oss://` 做一次推理重试；不再上传             |
| 用户觉得慢，但上传还在进行                   | 继续传。不中途改成 HTTPS                                 |
| 用户在 Host 里点取消                         | 中止，释放文件句柄和单飞锁                               |

### 8.5 分析与回答

| 情况                         | 结果                                                            |
| ---------------------------- | --------------------------------------------------------------- |
| 有画面也有对白               | 两者都要写                                                      |
| 有画面、没有可用声音         | 写画面，并明确说没听到可用声音                                  |
| 模型把数字听成中文读法       | 算成功，不要求字面量一致                                        |
| 回答写到模型最大输出仍被截断 | 接受为模型上限（当前 65536），不再加第二个工具做分段            |
| 401 / 403                    | 明确说检查 API Key 和接口地址，不要当网上传失败去重传本地大文件 |
| 模型返回空文本               | 视为错误                                                        |
| 429                          | `PROVIDER_RATE_LIMITED`，可稍后重试                             |
| 502/503                      | 首字节前可按现有规则重试至多 1 次                               |
| 推理超时                     | `PROVIDER_TIMEOUT`                                              |
| SSE 截断或格式不对           | `PROVIDER_RESPONSE_INVALID`                                     |
| 已出现首个有效文本后再失败   | 不重试                                                          |

### 8.6 并发、取消、Host

| 情况                                        | 结果                                                        |
| ------------------------------------------- | ----------------------------------------------------------- |
| 第二个 `analyze_video` 在第一个未结束时进来 | `VIDEO_ANALYSIS_BUSY`，不排队，不读第二个文件               |
| 两个不同 Host 各起一个进程                  | 各有一把锁，V2 不管跨进程互斥                               |
| Cursor 桌面里传 500 MiB 级文件              | 已验证可超过 60 秒。V2 仍应能跑 1 GiB（网速够时）           |
| Cursor ACP / 部分 CLI 默认 60 秒            | 可能被 Host 掐断。文档写明把超时调长；V2 不为此改成异步 job |
| Claude Code / Codex                         | 同一二进制。各自模板由用户填 `env`                          |
| 进程收到 SIGINT/SIGTERM，或 stdin 关闭      | 取消进行中的任务                                            |

### 8.7 安全与泄露

| 情况                                           | 结果                                         |
| ---------------------------------------------- | -------------------------------------------- |
| Agent 被诱导读取允许根外的视频                 | 拒绝                                         |
| 错误或日志里出现 key / policy / OSS / 绝对路径 | 不合格                                       |
| 用户主动允许并传入的视频含隐私                 | 会上传到百炼临时存储。这是用户授权，不是漏洞 |
| 同 Windows 账户抢先替换文件                    | 已缓解，未消除。不得宣传「完全无 TOCTOU」    |
| 内存随 1 GiB 文件线性涨到接近文件大小          | 不合格。必须保持流式                         |

### 8.8 人容易误解的情况

| 误解                    | 实际                                   |
| ----------------------- | -------------------------------------- |
| 超过 500 MiB 就不能分析 | V2 本地可以到 1 GiB                    |
| 超过 1 GiB 本地还能硬传 | 不能。先压缩、切段，或改 HTTPS         |
| 7 分钟一定超限          | 超限看体积，不看分钟数                 |
| 网慢会先弹窗让你选      | 不会。先传，失败后用错误文本建议 HTTPS |
| 把 key 填进 Tool 参数   | 不允许                                 |
| 需要先自己抽帧          | 不要。直接传路径或链接                 |
| 要先测连接或选模型      | 不要。配好后直接分析；模型是内部默认   |
| 这是已发布的 npm 包     | 不是。V2 仍是本机 MCP                  |

## 9. 给 Agent 看的错误文本（意向）

码不变。V2 只加长「下一步怎么做」，不加秘密。

| 错误码                             | 人话                                                                                                      | Agent 要不要立刻重试         |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `INVALID_VIDEO_INPUT`              | 输入无效。要用本地绝对 MP4 路径或公开 HTTPS。                                                             | 否                           |
| `VIDEO_PATH_NOT_ALLOWED`           | 这个本地路径不在允许目录里。请用户把目录写入 `QWEN_ALLOWED_ROOTS`，或改用 HTTPS。                         | 否                           |
| `VIDEO_NOT_FOUND`                  | 找不到或读不了这个视频。                                                                                  | 否                           |
| `UNSUPPORTED_VIDEO`                | 只支持普通 MP4。                                                                                          | 否                           |
| `VIDEO_FILE_TOO_LARGE`             | 超过本地允许上限（最高 1 GiB，且不超过服务当场上限）。请压缩、切段，或改用公开 HTTPS。                    | 否                           |
| `UPLOAD_POLICY_FAILED`             | 暂时拿不到上传凭证，稍后重试。                                                                            | 可稍后                       |
| `VIDEO_UPLOAD_FAILED`              | 本地上传失败，多半是网络或上传窗口不够。不要原文件再传一遍。请把视频放到公开 HTTPS 后，把链接交给本工具。 | 否（不要自动再传本地大文件） |
| `VIDEO_ANALYSIS_BUSY`              | 已有一个视频任务在进行，结束后再试。                                                                      | 稍后                         |
| `PROVIDER_RATE_LIMITED`            | 服务忙，稍后重试。                                                                                        | 按间隔                       |
| `PROVIDER_TIMEOUT`                 | 分析超时。                                                                                                | 可                           |
| `PROVIDER_UNAVAILABLE`             | 分析服务暂时不可用。                                                                                      | 可                           |
| `PROVIDER_RESPONSE_INVALID`        | 分析结果无效。                                                                                            | 可                           |
| `VIDEO_ANALYSIS_FAILED`            | 分析失败。                                                                                                | 视情况                       |
| 鉴权失败（可复用上一码或单独说明） | 检查 API Key 和接口地址。                                                                                 | 否                           |

`VIDEO_UPLOAD_FAILED` 在 V2 改为「不要自动重传本地大文件」。这和 v1「可由用户决定重试」不同：用户可以改用 HTTPS 再调，但 Agent 不得把同一本地大文件连打两次。

## 10. 两条推荐用法

**网速正常、文件 ≤ 1 GiB**

1. 把文件夹写入 `QWEN_ALLOWED_ROOTS`。
2. Agent 传本地绝对路径。
3. 直接问画面和声音。不必传长度参数。

**网速慢，或文件 > 1 GiB**

1. 用户自己把 MP4 放到可公网打开的 HTTPS。
2. Agent 传该链接。
3. 本机不上传、不下载。
4. 同样不必传长度参数。

## 11. V2 不做

- 配置 GUI、系统弹窗、进度面板。
- 图片 Tool、独立音频 Tool、状态查询 Tool、测试连接 Tool。
- 启动时自动打百炼做连通探测。
- 转码、压缩、切段、抽帧、烧字幕。

## 12. 怎样算 V2 写完、能做

读完这份文档后，下列句子都必须已经有答案：

1. 本地最高传多大？
2. 谁决定能不能传：用户配置、当场政策，还是两者取小？
3. 什么时候直接传，什么时候改 HTTPS？
4. 「提示」是窗口还是错误文本？
5. 哪些路径和链接必须拒？
6. 第二个任务来了怎么办？
7. 回答能写多长？谁决定？
8. 密钥放哪，什么地方绝对不能出现？
9. 配完 MCP 怎么知道连得上？要不要单独测连接？
10. 哪些事明确不做？

实现完成标准：

- 新机器只靠模板 + 用户自己的 key 能在 Cursor 分析本地 MP4。
- 默认本地上限 1024 MiB；用户仍可收紧。
- 501–1024 MiB 且不超过当场政策的本地文件，不再被 500 MiB 产品硬顶拒绝。
- 上传超时/凭证过期的错误文本含 HTTPS 建议，且不自动重传。
- Tool 名仍是 `analyze_video`；公开字段只剩 `video` 和 `question`。
- 回答不再被 1024/8192 卡住；内部按模型最大输出。
- 质量门保持现有门槛。
- 不发布、不推送，除非另说。
