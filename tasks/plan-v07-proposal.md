# 下一阶段优化路线（待审阅）

> **历史路线，下一大版本不再按 C/D 的三 Tool、FFmpeg 测量、综合审核实施。** 当前接手计划见 [`plan-next-major-media-gateway.md`](plan-next-major-media-gateway.md)。本文件的 A/B 阶段记录保留为已有工作的历史证据。

状态：**目标与顺序提案，尚未开始实现**。当前发布版为 v0.6.1；稳定接口是 `analyze_video(video, question?)`。本路线依据 [`SPEC_V07_PROPOSAL.md`](../docs/SPEC_V07_PROPOSAL.md)、[ADR 0018](../docs/decisions/0018-v07-tool-surface.md)、[ADR 0019](../docs/decisions/0019-v07-local-measurement.md)、[ADR 0020](../docs/decisions/0020-user-granted-local-media.md)。具体任务见 [`todo-v07-proposal.md`](todo-v07-proposal.md)。

## 产品目标与优先级

| 优先级          | 用户最终能做什么                                                         | 当前缺口                                                                       | 退出条件                                                     |
| --------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| P0 输入体验     | 在 Codex 中明确选择视频后，无论它在哪个文件夹，都能交给 `analyze_video`  | 当前本地路径必须位于 `QWEN_ALLOWED_ROOTS`；Codex 拖入附件到 MCP 的交接尚未验证 | 验证真实宿主；实现可验证的单文件授权；未授权同一路径仍被拒绝 |
| P1 现有视频链路 | 大视频上传、超时、取消、缓存和失败提示可预期，能区分宿主中断与服务端失败 | 有真实使用中的中断案例，但需在当前版本复现并定位                               | 针对复现问题修复，模拟和真实宿主回归通过，错误不泄密         |
| P2 声音能力     | 分析纯音频或 MP4 音轨，并得到有来源的响度、峰值、静音等数值              | 当前仅有视频内嵌声音的抽样语义判断，无独立音频 Tool 或确定性测量               | `analyze_audio` 与测量有独立结果、覆盖范围和失败标记         |
| P3 综合审核     | 对画面、声音、字幕和技术情况给分项意见及证据范围                         | 当前无法交叉核验，也不能证明整片字幕/技术质量                                  | `audit_media` 不把抽样判断写成全量核验，权利状态单列         |
| P4 交付体验     | 新用户能诊断配置、理解限制并在声明支持的宿主走通流程                     | 文档与 Tool 指引仍以允许根和单 Tool 为准                                       | 安装、doctor、示例、契约和宿主 E2E 与发布版一致              |

P0 不代表取消现有大小、时长或供应商政策限制；它只解决“文件夹不在允许根内”的授权摩擦。P2、P3 涉及新公开 Tool 和外部运行时，须先审定接口与依赖。P1 只修已复现问题，不预设大规模重写。

## 依赖与实施顺序

```text
Codex 附件交接探针
  → 确认单文件授权方案 → 跨目录视频端到端 → 现有链路回归
                                          ↓
                              音频协议 / 运行时验证
                                          ↓
                              analyze_audio + 确定性测量
                                          ↓
                              字幕输入与 audit_media
                                          ↓
                              文档、宿主验证、发布候选
```

### 阶段 A：先打通用户输入

1. 用无私密短 MP4 验证 Codex 是否接受拖入、如何表示附件、MCP 能否得到可信引用或流；不请求付费 API。**已完成 2026-09-22**：接受拖入，但只给模型路径文本，MCP 无来源证明。
2. 根据实测选择交接方式。**已完成**：宿主能力不足，用户否决确认弹窗，采用安装级开关 `QWEN_ALLOW_ANY_LOCAL_VIDEO`（默认 `off`），见 [ADR 0021](../docs/decisions/0021-allow-any-local-video-opt-in.md)。
3. 实现本地 MP4 的只读校验与上传开关；沿用格式、大小、时长和脱敏校验。**代码已实现、CLI 已验证；2026-09-23 桌面 GUI 已用公开短 MP4 完成一次拖入和真实付费分析**。验证范围与未覆盖条件见 [`todo-v07-proposal.md`](todo-v07-proposal.md) 的 A 段与 [`deepseek-v07-handoff.md`](deepseek-v07-handoff.md) 的“A 批状态”。

检查点：用户在任意目录选定视频后可分析（开关打开时）；开关关闭时 Agent 填写的根外路径仍被拒绝。“拖入一次即自动分析”是开关打开后的既有行为，不再依赖宿主附件交接。

### 阶段 B：稳定现有视频流程

1. 用当前版本复现中断/超时等实际问题，记录本地阶段、Host 表现和安全错误码。
2. 逐项修复有证据的问题，核对取消后的句柄释放、上传缓存命中与失效、进度提示和失败后的重试指引。

检查点：已有 `analyze_video` 契约不变；小视频与较大视频的模拟测试通过，真实宿主验证不出现静默挂起。真实百炼调用需另获授权。

### 阶段 C：独立音频与确定性测量

1. 冻结 `analyze_audio` 输入格式和 provider 协议，确认模型是否真的读取纯音频；付费 live 试验另获授权。
2. 审定 FFmpeg/ffprobe 外部运行时策略，先做 ffprobe/解码与 LUFS、true peak、静音、峰值等最小测量集。
3. 将听到的内容、测得的数值和推断分别标记；缺音轨、部分解码或运行时缺失时返回 `incomplete`。

检查点：独立音频和视频音轨案例均可用；模型不能凭听感生成技术数值。新增 Tool、运行时和依赖须按提案审批。

### 阶段 D：字幕与综合审核

1. 先支持可解码字幕轨及用户 sidecar；核对时间段、重叠、相邻字幕，不承诺无证据的全文正确。
2. `audit_media` 汇合画面、声音、字幕与技术来源，输出分项发现、覆盖范围和未核验项。
3. 版权/商业授权单独给状态，不能从画面和声音质量推导发布许可。OCR 留待引擎和验证方案明确后再决定。

检查点：无字幕、无音轨、连续字幕、错字、部分媒体和权利未知的夹具均不会得到虚假的“完整通过”。

### 阶段 E：交付与发布候选

同步 API 契约、安装示例、`--doctor --json`、Server instructions 与 Tool 描述；执行 typecheck、lint、format、单测、coverage、build 和声明支持的宿主 E2E。发布、推送和付费 live 测试分别按仓库规则另行授权。

## 决策点

1. Codex 拖入视频能否给 MCP 一个可信的单文件引用？这是 P0 的首个技术门槛，不能仅凭路径或 Agent 文字推定。
2. 是否接受新 `analyze_audio` / `audit_media` 公开接口，以及 FFmpeg/ffprobe 的安装与调用策略？见 ADR 0018、0019。
3. 若供应商对音频格式或上传有限制，以真实协议证据收缩支持范围；不把未验证格式写为已实现。
