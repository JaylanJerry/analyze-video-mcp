## 当前基线与先决事实

- 实施前基线只注册 `analyze_video(video, question?)`；本地 MP4/MOV 与 HTTPS、百炼临时上传、缓存、SSE 和错误防护已存在。当前工作区分支改为唯一 `analyze_media`，npm 已发布 `0.6.1` 仍是旧 Tool；接手时以 `git status`、提交历史和现行代码为准。
- `src/server.ts` 混有 Tool 绑定、提示词提纲、证据纠错、返回格式与主流程；`src/evidence.ts` 是旧报告层。`src/media.ts` 负责本地视频授权/探测，`src/upload.ts` 与 `src/upload-cache.ts` 负责上传，`src/bailian.ts`/`src/sse.ts` 负责模型协议。先增加新路径的测试与窄接口，再移除旧路径，避免一次性推倒全部安全边界。
- 纯 MP3 模型协议与临时上传方式在计划制定时尚未完成真实验证；当前已用获授权的无私密样本在 `qwen3.8-omni-flash` 上通过，具体模型、用量与范围见任务清单和 `docs/PROVIDER_PROTOCOL.md`。其它模型、宿主 MP3 路径及费用金额不能从该证据推定。

## 阶段与检查点

### A. 契约和风险先行

冻结 `analyze_media(media, prompt)`、成功元数据的字段出现条件和规格中的错误码迁移表。先写契约测试：只一个 Tool、必填 prompt、无服务端业务模板、文本与结构化回答一致且路径、密钥、OSS 引用不泄露。公开 HTTPS 只沿用视频直连，不把远端 MP3 猜成可分析音频。新 Tool 只接受 `MEDIA_ALLOWED_ROOTS` / `MEDIA_ALLOW_ANY_LOCAL_FILE` 作为本地授权配置，默认拒绝；旧视频授权变量不自动迁移，doctor 和安装说明引导用户显式迁移。

**检查点 A：** 文档和 mock 契约一致；旧版行为仍能通过当前测试，尚无真实上传或依赖变化。

### A-P. MP3 协议可行性探针

先以 mock 固定 Chat Completions 的 `input_audio.data`、`format: mp3` 和临时 URL 的 OSS resolve Header；核对安装模型的音频输入能力。只有另获用户对无私密小样本上传及付费调用的明确授权后，才进行真实协议探针，记录模型、地域、请求形状、服务商返回及用量，不记录凭证或媒体内容。若未获授权，B 阶段与 C 阶段的模拟工作可以继续，但不能完成 MP3 真实验收；若协议失败，暂停 MP3 交付并提交可复核证据和最小规格调整。

**检查点 A-P：** mock 协议已固定；真实组合状态单独记为“已验证 / 失败 / 待授权”，不以 mock 结果冒充服务商证据。

### B. 打通 MP4/MOV 的新薄路径

复用已授权句柄、格式探测、上传和 SSE；把模型提问与回答从证据报告层剥离。保留脱敏、错误分类、取消、进度与上传复用。对宽泛和具体问题各做一个模拟端到端，确认不追加九段提纲、不要求证据 JSON、不进行纠错再请求；清晰记录移除的旧测试与替代断言。

**检查点 B：** 现有视频样本在新入口模拟端到端通过；旧安全反例不退化；默认 `npm test` 无网络或费用。

### C. 补纯 MP3

实现 MP3 内容识别、有界大小/时长与本地授权；在百炼适配器中按已固定的 `input_audio` 契约构造文本输出请求。与视频共用安全上传和响应处理，缓存按媒体种类、模型、端点及账号/凭证身份隔离；身份变更或无法安全确认时失效。模拟正常、坏文件、超限、取消与失效。A-P 未验证或失败时不得声称 MP3 真实可用；若 `oss://` 音频不可用，停在明确错误并提交证据和最小替代设计，不隐式 Base64 或换云。

**检查点 C：** mock 端到端通过；真实支持状态与已测证据分开记录。无授权时此阶段不得进行付费 live。

### D. 清理迁移与交付

新路径稳定后移除旧 `analyze_video` 注册、固定提纲、证据 JSON 门禁、自动纠错重试及仅服务于旧报告的冗余逻辑。任何有独立安全价值的能力（如脱敏和内容检查错误）应留下。同步包示例、doctor、当前 API 契约、架构、安全、服务商协议、README、Server instructions 与 Tool 描述；给已有安装者明确旧 Tool/字段/配置/错误码迁移表。

**检查点 D：** MCP 列表恰好一个新 Tool，独立打包安装和 stdio 握手成功，全部本地质量门与 Node 22/24 CI 通过；文档没有把旧提案当成已实施。

### E. 真实验收与发布准备

在用户针对实际文件/服务商调用另行授权后，用无私密短 MP4/MOV/MP3 和一个较长的无私密视频检验模型是否返回画面/声音内容、上传复用、失败码、超时与宿主进度。记录文件哈希、模型、请求次数、费用可用数据、脱敏结果和不确定项。A-P 的协议成功只证明请求可用；只有三格式宿主路径和声音/画面结果均有证据后才声明支持。发布、推送和 tag 另获明确授权。

## 风险与收敛办法

| 风险                                   | 收敛办法                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------- |
| MP3 文档支持与本项目临时上传协议不一致 | 先隔离音频 content block，mock 验证结构，再单独授权小样本 live；失败时停住音频交付并报告证据 |
| 删旧证据层时连带删掉脱敏或错误防护     | 先给这些独立安全行为补回归测试，再删旧报告专用代码                                           |
| 老配置升级后扩大本地读取范围           | 新权限显式配置、默认拒绝；迁移测试覆盖旧开关打开仍不能上传根外 MP3                           |
| 追问的缓存被误解为模型记忆或免费       | 返回 `upload_reused` 事实；文档说明每次分析仍可计费且需 Agent 自带前文                       |
| 更换百炼账号后命中旧临时 URL 缓存      | 缓存身份隔离；无法安全确认同一账号/凭证身份时使旧项失效，不保存凭证本身                      |
| 重构期间主分支长期不可用               | 每个任务交付可构建的纵向切片；临时未发布代码不更新默认安装或发布标签                         |
| 服务商内容拒绝被误判为文件故障         | 保留 ADR 0023 的安全分类与不可自动重试行为                                                   |

## 范围和审批边界

现有 TypeScript/Node/MCP SDK、`msw` 和零真实请求默认测试不变。新生产依赖、FFmpeg 或其它外部运行时、付费 live、第二服务商、推送与发布均不包含在本计划的自动授权里。DeepSeek 可以推进不依赖这些事项的实现与模拟验证；遇到协议事实缺口应提交可复核证据，而不是把未验证路径标成完成。
